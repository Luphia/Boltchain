# ADR 0010：內建區塊鏈瀏覽器

- 狀態：已採納並實作第一階段（2026-09-26，M6）
- 決定者：專案負責人
- 相關：ADR 0009（IPFS 閘道、修剪）

## 決定

節點內建一個唯讀的區塊鏈瀏覽器，用 `--explorer` 開啟。它和 IPFS 閘道共用 `--gateway` 的 HTTP 位址，預設 `127.0.0.1:8080`，公開與否由營運者決定。

- **主要使用者是一般使用者**：首頁、區塊、交易、地址、驗證者、epoch 頁，以及可以搜尋區塊高度、雜湊、地址、CID 的搜尋框。
- **介面語言**：繁體中文與英文，依瀏覽器語言自動選擇，可以手動切換。
- **前端**：單一 HTML 檔（`crates/node/src/explorer/index.html`），原生 JavaScript，沒有建置步驟與外部相依，編譯時用 `include_str!` 打包進執行檔，因此仍可重現建置。
- **API**：`/api/...` 回傳 JSON，資料直接讀節點的資料庫與系統合約狀態，不需要另外的資料庫或索引服務。

## 地址索引

- **資料表**：`addr_tx`，鍵是 `地址 ‖ 區塊號 ‖ 交易序號`，值是角色旗標：發出、接收、建立合約、代幣轉帳的一方、發出轉帳事件的代幣合約。
- **維護方式**：開啟後，新區塊寫入時一起建立索引；鏈重組倒回區塊時一併刪除。舊區塊由背景執行緒從最新往最舊補建，每批 200 塊。
- **範圍限制**：已修剪或早於快照起點的區塊沒有內容，補建會停在那裡。頁面會說明索引從哪一塊開始涵蓋。
- **代價**：每筆交易約 3–5 個條目，每個條目約 40 bytes。
- **建議**：對外提供瀏覽器的節點搭配 `--archive`，否則舊 epoch 的交易內容可能已被修剪。

## Boltchain 特有的呈現

- **共識階段**：以進度條顯示挖礦 → 質押確認 → PoS 三個階段，以及距離下一個門檻還差多少驗證者、質押與連續達標的 epoch。
- **區塊頁**
  - 顯示 IPFS 內容位址：envelope、header 與交易分塊的 CID，並可下載這個區塊的 CAR 檔。
  - **在瀏覽器中驗證**：直接從閘道取回原始 IPFS 區塊，在瀏覽器裡以 JavaScript 計算雜湊（keccak-256 與 sha-256 都用純 JS 實作，因為以 IP 位址提供的 http 頁面不能使用 WebCrypto），核對 header 雜湊等於區塊雜湊，且 envelope 與交易分塊都符合各自的 CID，不必信任這個節點。
- **交易解碼**：系統合約的呼叫（register、deposit、requestExit、withdraw、setFeeRecipient、setPeer、claim、submitEvidence）與 ERC-20 的 transfer、approve、transferFrom 會解碼成易讀格式；`Transfer` 事件顯示為代幣轉帳。
- **驗證者**：質押額、狀態、累積獎勵、本 epoch 席位、是否登記了歷史資料節點；單一驗證者頁另外列出近 10 個 epoch 的委員會席位與儲存抽查結果。
- **Epoch**：委員會、epoch 索引 CID（可下載整個 epoch 的 CAR）、抽查小組與任務結果。

## 之後

- 第二階段：圖表（難度、出塊時間、燃燒、質押）、代幣頁（持有者與轉帳列表）。
- 第三階段：連接 MetaMask 直接質押與領取獎勵；多節點比對，作為分叉警報。
- API 目前沒有速率限制。公開時建議放在反向代理之後；速率限制會和 peer scoring 一起做。
